# 睡眠模式开发与使用说明

本地分支 `codex/sleep-mode`，基线 `83e3302`，应用版本为 `0.3.1`。本功能替代旧的按小时定时调暗，不依赖 OyasumiVR、MQTT 或 Root。

## 使用

1. 按现有向导连接 USB 或无线 ADB。在设置中选择睡眠亮度（默认物理 0、软件 5%）。
2. **手动进入**：点击主页“进入睡眠”。程序验证设备、启动防休眠、保存恢复记录，再调暗。SteamVR 不可用时物理调暗仍可执行，软件结果显示未确认／错误。
3. **自动监测**：开启开关后立即尝试连接并启动防休眠，成功后才建立监测窗口。默认连续低活动 15 分钟，再等待 20 秒确认。支持 5–60 分钟和五档灵敏度。
4. **校准**：戴好头显，点击校准并自然静止约 10 秒；明显移动重置计时。校准仅估计追踪噪声。建议实机测试后调整灵敏度。
5. **退出睡眠**：恢复进入前的软件亮度和开关，以及物理恢复值；防休眠继续运行。退出后默认冷却 15 分钟，然后重新建立完整窗口。普通头部运动不会自动唤醒。
6. 睡眠期间主页滑块仅调整当前软件亮度，不覆盖睡前快照和正常手动预设。“恢复 100%”立即关闭软件遮挡；不退出睡眠、不改变物理亮度。需要两种亮度一起恢复时点击“退出睡眠”。
7. 监测开关及校准即时生效；其他参数使用设置页的应用／取消。监测启用状态跨重启保存；启动后必须重新连接、启动防休眠并采集完整窗口。
8. 显式停止防休眠会暂停并关闭自动监测意图，避免后台擅自重新启动。睡眠状态不会因此自动退出。

## 物理恢复限制

当前不依赖不受支持的 `cmd display get-brightness`，也不把 `screen_brightness` 的设置值除以 255 当成 DisplayManager 精确值。记录原系统设置和模式，但 DisplayManager 使用配置中的回退恢复值，默认 **0.5**。这不是精确还原原物理亮度。

调暗前将恢复快照写入应用配置目录 `sleep-recovery.json`，绑定 `ro.serialno`。无法可靠获取设备序列号或无法保存快照时拒绝调暗。恢复时验证同一设备，尝试原系统设置、模式和 DisplayManager 回退值；即使某个设置写入失败仍尝试其他恢复步骤。全部成功才删除记录，失败保留重试入口。异常关闭或重启后显示待恢复记录，不自动对其他设备写入。

正常退出先停止 Helper／清除遮罩，再限时尝试物理恢复。设备不可达或系统强制结束时，恢复记录留待下次连接处理。

## 检测算法与边界

- 沿用同一个 Helper 的约 20 Hz 循环；位置增量为欧氏距离，旋转为归一化四元数绝对点积夹角，处理 q/-q 和 180° 旋转。
- 最多保留 3600 个一秒统计桶及 400 个校准样本。报告 10 秒、1／5／10／15 分钟及自定义窗口的原始累计平移／旋转，约 1 Hz 对外更新，心跳保持原频率。
- 校准使用归一化到 20 Hz 的样本增量 95 分位估计噪声；判定量扣除该噪声。中等灵敏度初始允许率为 0.003 m/s、0.3°/s，五档系数 0.5／0.75／1／1.5／2；阈值随窗口时长缩放。它们是待实机调校的工程初值，不是已证实的睡眠阈值。
- 一秒明显活动超过 0.08 m 或 15°、短窗口超阈值、明确控制器按键或轴输入会重置连续低活动计时。完整窗口不足不得触发；确认期间活动取消候选。
- 无效位姿、采样间隔超过 250 ms、SteamVR／Helper 重启重建窗口。单调时钟避免系统时间调整干扰。
- 控制器输入使用 OpenVR 提供的传统控制器状态，驱动不提供时标记能力受限。HMD 连接并不等于佩戴；依赖运行时活动和追踪信号，不能保证识别所有摘下头显情况。VD 断流一般使追踪失效，但本工具不直接读取 VD／VRChat 在线状态。
- **静止只能表示疑似入睡**。坐着不动、把头显放在桌上仍可能误判。真实噪声、翻身容错、长时间识别效果需 PICO 实机确认。

## 状态与架构

`IDLE → MONITORING → SLEEP_PENDING → SLEEPING_AUTO`；手动进入使用 `SLEEPING_MANUAL`。运行环境失效或冷却为 `PAUSED`，需处理的错误为 `ERROR`。防休眠、监测意图、睡眠状态、物理应用、软件应用和恢复记录分别管理。

Rust 睡眠服务拥有恢复快照、物理写入锁、操作代次及监测代次。进入／退出互斥提交；旧代次不能覆盖新状态。软件恢复不等待 ADB 锁，最新手动亮度操作取消 Helper 渐变。

既有 `Desired`／`Report` 增加可缺省的 detector／detection 和 fade_ms 字段，保留原亮度命令。关闭遮罩但继续监测时保留一个 OpenVR 会话，最多一个 Overlay。仍使用固定 DLL、既有侧车路径、重启上限和 Windows Job 清理。

新增 Tauri 命令：`get_sleep_status`、`enter_sleep`、`exit_sleep`（含恢复重试）、`set_sleep_monitoring`、`calibrate_sleep`；状态事件 `sleep-status`。UI 关闭设置页后服务继续运行。

## 配置迁移与版权

增加嵌套 `sleep` 配置并提供默认值；旧 dim_delay_hours、auto_dim_steamvr、auto_dim_steamvr_percent 作为未知字段兼容读取，保存时不再写出。旧定时设置不会开启新自动监测。IP、连接方式、唤醒间隔、正常软件亮度保留；语言／主题仍由原前端存储。

无新增运行时依赖。参考 OyasumiVR 的窗口统计和自动化思路，独立适配本项目；保留 [MIT 版权声明](LICENSES/LICENSE-OyasumiVR.txt)，安装器沿用 LICENSES 通配符分发。

参考：[运动统计](https://github.com/Raphiiko/OyasumiVR/blob/develop/src-core/src/openvr/sleep_detector.rs)、[自动化判定](https://github.com/Raphiiko/OyasumiVR/blob/develop/src-ui/app/services/sleep-detection-automations/sleep-mode-for-sleep-detector-automation.service.ts)。

## 实机验收步骤（待 PICO 4 Ultra 实机测试）

1. USB／无线连接各验证一次，进入睡眠前防休眠关闭，确认进入后自动启动且退出后继续运行。
2. 软件正常值设为 35%，物理恢复值设为可接受值；进入默认 0／5% 睡眠，再退出。验证双眼、边缘、跟踪、声音、VD 和 VRChat 在线状态。
3. 进入渐变时点击恢复 100%，确认不再变暗；睡眠中微调，然后退出确认原 35% 恢复。
4. 开启监测、校准、调至 5 分钟测试完整窗口；运动和控制器操作应重置进度，确认倒计时应可取消。
5. 睡眠后转头不自动调亮；手动退出后冷却且重新建立窗口。
6. SteamVR 重启、Helper 异常退出、摘戴头显、VD 断流分别验证窗口失效和错误显示。
7. 调暗后断开 ADB，点击退出；软件应恢复、物理显示失败。重连同一设备后重试。
8. 睡眠中退出应用及异常终止，再次启动检查恢复提示。重启 Windows 后验证监测偏好但不恢复旧进度。
9. 持续使用一晚，记录误判、噪声、资源占用和在线／音频状态；这一步不能由短时自动测试替代。
